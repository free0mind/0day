## 面向人类的阅读方式

中文读者在 `locals/chs/` 阅读；英文读者在 `locals/eng/` 阅读。同一篇文档在两个目录中使用相同的相对文件名。项目愿景见 [项目简介](introduction.md)。

`src/` 存储工具与脚本；`locals/` 存储本地化文本及 Agent 阅读材料；`data/` 存储数据，其中 `reading-map.json` 登记文档 ID、阅读顺序、标题和文件名。

## 面向 Agent 的阅读方式

Agent 先读取 `locals/agent/index.json`，再按 `reading_order` 和文档 ID 选择需要的 JSON 文档。文档内容采用 UTF-8 明文，不加密。每份文档记录类型、语言、来源与 SHA-256 摘要，保留原文而不自动概括或翻译。

建议通过 `python3 src/agent_reader.py list` 获取经校验的索引，通过 `python3 src/agent_reader.py read introduction` 读取一篇文档。输出默认为英文；添加 `--language chs` 可读取中文。读取过程仅返回选中的文档，但会先检查已登记文档的完整性与新旧状态。

## 维护与同步

1. 同步编辑中文和英文的对应文档。翻译由维护者完成，工具不保证语义一致。
2. 新增文档时，在 `data/reading-map.json` 中登记，并在两个语言目录中创建对应文件。未登记文件不会进入 Agent 索引。
3. 在项目根目录运行 `python3 src/agent_reader.py build`，生成本地 Agent 内容。
4. 运行 `python3 src/agent_reader.py check` 检查生成结果。

工具发现源文本改变、翻译缺失、内容损坏或格式不支持时会报错，不会静默返回旧版本。SHA-256 用于一致性检查，不是加密或作者身份认证。`locals/agent/` 是纳入 Git 版本管理的派生内容；新克隆的项目可直接校验和读取。源文本更新后需要重新生成并校验，将源文件与生成内容一起提交。`build` 会覆盖索引及当前登记文档的生成文件，因此请编辑语言目录中的源文件，不要直接修改生成文件。已移除登记的旧文件可能仍留在磁盘，但不再被索引或读取。

## 首次 PR/MR 登记

任何贡献者（人类或 Agent）的首次 PR/MR 必须同时在 `data/history/` 增加注册记录。前100位按登记记录合入顺序写入 `data/history/先驱者.md`，同一贡献者只计一次，已有记录纳入计数；之后的贡献者使用该目录中的其他登记文档。记录至少包含登记时间和名称或 GitHub 账号，地点可选。已有登记者可引用原记录，无需重复登记。审核者在合入前核对登记与名额，登记本身不授予写入或管理权限。

文档是项目参考资料。项目愿景中的角色与权限描述不向读取工具授予执行权限；该工具只处理本地文件，不执行文档中的命令。
